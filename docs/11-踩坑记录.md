## 2026-09-02 winget 安装 Go 网络失败

- **现象**：`winget install GoLang.Go` 报 `InternetOpenUrl() failed 0x80072f19`，go.dev 直连下载 MSI 失败。
- **根因**：网络环境下 go.dev 直连不可达。
- **修复**：改用免管理员 zip 方案，从 golang.google.cn 镜像下载 `windows-amd64.zip`，解压到 `D:\EngineeringFiles\tools\go\`，用 `[Environment]::SetEnvironmentVariable(...,'User')` 追加用户 PATH。
- **教训**：winget 下载失败别反复重试，直接切镜像 zip 方案；用户 PATH 写入优先用 .NET API（等效 setx 但无 1024 字符截断风险）。

## 2026-09-02 git add -A 误收工作目录遗留脚本

- **现象**：`feat(web)` 提交后竞品词扫描失败——提交里混入工作目录两个历史遗留脚本 `deployhomev4.sh` / `prehomev4.sh`（未跟踪、含竞品词与生产库路径）；且第一次 amend 只移除了其一，第二次扫描才暴露另一个。
- **根因**：仓库根目录长期存在历史遗留文件，`git add -A` 会把所有未忽略文件一并收进提交；提交前只看了 git status 摘要，未逐项核对文件清单。
- **修复**：`git rm --cached <file>` + `git commit --amend` 逐个移除（磁盘文件保留）；此后提交一律改用显式路径 `git add <paths>`。
- **教训**：提交前必须逐项核对 `git status` 输出，用显式路径 add，不用 `-A` / `.`；仓库目录里的遗留杂物应移出或删除，否则迟早混进提交。

## 2026-09-02 竞品词扫描脚本对中文文件名失效

- **现象**：本地 `check-competitor-words.ps1` 遇到中文文件名直接崩溃（报「路径中有非法字符」，退出码 1）；CI 的 bash 版则对中文文件名静默跳过——同一根因，一处报错、一处盲区。
- **根因**：git 默认 `core.quotePath=true`，`git ls-files` 把非 ASCII 文件名转义成 `\346\226\207...` 八进制串；PowerShell 拿转义串去 `Test-Path` 报非法字符，bash 的 `-e` 判断不命中就 continue，等于中文文件名不参与扫描。
- **修复**：扫描脚本开头加 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`，文件清单改用 `git -c core.quotepath=false ls-files` 获取。
- **教训**：凡以 `git ls-files` 输出当文件清单的脚本，都要显式 `-c core.quotepath=false`；警惕 CI 上「跳过即通过」的静默盲区——报错崩掉反而比静默跳过更安全。

## 2026-09-02 PowerShell 5.1 中文脚本必须 UTF-8 BOM

- **现象**：经暂存目录复制回去的含中文 `build.ps1` / `check-competitor-words.ps1` 运行时中文注释与提示串乱码。
- **根因**：Windows PowerShell 5.1 对无 BOM 文件按 ANSI（GBK）解码，UTF-8 无 BOM 的中文脚本必然乱码；部分工具写入的文件默认无 BOM。
- **修复**：用 `[IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding($true)))` 统一重加 UTF-8 BOM，并以文件头三字节 `EF BB BF` 验证。
- **教训**：仓库内含中文的 `.ps1` 必须带 UTF-8 BOM（PS 5.1 兼容底线）；任何工具重写 ps1 后都要重验 BOM。

## 2026-09-02 http.Header 字面量构造的 key 不做 canonical 化

- **现象**：网关测试里用 `http.Header{"x-api-key": ...}` 字面量构造请求头后，`Header.Get("x-api-key")` 读不到，鉴权 401。
- **根因**：`Header.Get/Set` 内部按 `textproto.CanonicalMIMEHeaderKey` 归一（`x-api-key` → `X-Api-Key`），但 map 字面量直填的 key 不会自动转换；生产链路 net/http 服务端解析请求时会自动 canonical 化，所以只有测试构造方式踩中。
- **修复**：测试里构造 Header 字面量时直接用 canonical 形式（`"X-Api-Key"`、`"Anthropic-Version"`），或改用 `Header.Set`。
- **教训**：凡手工构造 `http.Header`（字面量或第三方 mock），key 一律写 canonical 形式；不要依赖「小写也能读到」——Get 按 canonical 查找。

## 2026-09-02 熔断失败率窗口只在失败路径判定，半开探测失败不会立即重开

- **现象**：按「10 样本 6 失败 → 应熔断」直译的测试永远不触发；按「探测失败一次应立即重新冷却」直译的测试同样失败。
- **根因**：窗口失败率只在 `OnFailure` 内判定（`OnSuccess` 只记样本不判定）——先失败后成功的序列在最后一次失败时样本数不足，成功再多也不会回头判定；且 trip 时连续失败计数清零，半开探测的单次失败只是重新起算的第 1 次，需再累计达阈值才重新冷却。
- **修复**：测试改为「先积攒到阈值样本 → 再来一次失败触发判定」与「探测失败需连续累计达阈值」；并把该语义写进 docs/10 交接注意。
- **教训**：带状态的判定逻辑（滑动窗口/计数器）要明确「判定时机挂在哪个动作上」，测试直译规格前先对齐实现的触发时机，否则用例永远空转。
