## 2026-09-02 winget 安装 Go 网络失败

- **现象**：`winget install GoLang.Go` 报 `InternetOpenUrl() failed 0x80072f19`，go.dev 直连下载 MSI 失败。
- **根因**：网络环境下 go.dev 直连不可达。
- **修复**：改用免管理员 zip 方案，从 golang.google.cn 镜像下载 `windows-amd64.zip`，解压到 `D:\EngineeringFiles\tools\go\`，用 `[Environment]::SetEnvironmentVariable(...,'User')` 追加用户 PATH。
- **教训**：winget 下载失败别反复重试，直接切镜像 zip 方案；用户 PATH 写入优先用 .NET API（等效 setx 但无 1024 字符截断风险）。

## 2026-09-02 git add -A 误收工作目录遗留脚本

- **现象**：`feat(web)` 提交后竞品词扫描失败——提交里混入工作目录两个历史遗留脚本 `deployhomev4.sh` / `prehomev4.sh`（未跟踪、含竞品词与生产库路径）；且第一次 amend 只移除了其一，第二次扫描才暴露另一个。
- **根因**：仓库根目录长期存在历史遗留文件，`git add -A` 会把所有未忽略文件一并收进提交；提交前只看了 git status 摘要，未逐项核对文件清单。
- **修复**：`git rm --cached <file>` + `git commit --amend` 逐个移除（磁盘文件保留）；此后提交一律改用显式路径 `git add <paths>`。
- **教训**：提交前必须逐项核对 `git status` 输出，用显式路径 add，不用 `-A` / `.`；仓库目录里的遗留杂物应移出或删除，否则迟早混进提交。

## 2026-09-02 竞品词扫描脚本对中文文件名失效

- **现象**：本地 `check-competitor-words.ps1` 遇到中文文件名直接崩溃（报「路径中有非法字符」，退出码 1）；CI 的 bash 版则对中文文件名静默跳过——同一根因，一处报错、一处盲区。
- **根因**：git 默认 `core.quotePath=true`，`git ls-files` 把非 ASCII 文件名转义成 `\346\226\207...` 八进制串；PowerShell 拿转义串去 `Test-Path` 报非法字符，bash 的 `-e` 判断不命中就 continue，等于中文文件名不参与扫描。
- **修复**：扫描脚本开头加 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`，文件清单改用 `git -c core.quotepath=false ls-files` 获取。
- **教训**：凡以 `git ls-files` 输出当文件清单的脚本，都要显式 `-c core.quotepath=false`；警惕 CI 上「跳过即通过」的静默盲区——报错崩掉反而比静默跳过更安全。

## 2026-09-02 PowerShell 5.1 中文脚本必须 UTF-8 BOM

- **现象**：经暂存目录复制回去的含中文 `build.ps1` / `check-competitor-words.ps1` 运行时中文注释与提示串乱码。
- **根因**：Windows PowerShell 5.1 对无 BOM 文件按 ANSI（GBK）解码，UTF-8 无 BOM 的中文脚本必然乱码；部分工具写入的文件默认无 BOM。
- **修复**：用 `[IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding($true)))` 统一重加 UTF-8 BOM，并以文件头三字节 `EF BB BF` 验证。
- **教训**：仓库内含中文的 `.ps1` 必须带 UTF-8 BOM（PS 5.1 兼容底线）；任何工具重写 ps1 后都要重验 BOM。

## 2026-09-02 http.Header 字面量构造的 key 不做 canonical 化

- **现象**：网关测试里用 `http.Header{"x-api-key": ...}` 字面量构造请求头后，`Header.Get("x-api-key")` 读不到，鉴权 401。
- **根因**：`Header.Get/Set` 内部按 `textproto.CanonicalMIMEHeaderKey` 归一（`x-api-key` → `X-Api-Key`），但 map 字面量直填的 key 不会自动转换；生产链路 net/http 服务端解析请求时会自动 canonical 化，所以只有测试构造方式踩中。
- **修复**：测试里构造 Header 字面量时直接用 canonical 形式（`"X-Api-Key"`、`"Anthropic-Version"`），或改用 `Header.Set`。
- **教训**：凡手工构造 `http.Header`（字面量或第三方 mock），key 一律写 canonical 形式；不要依赖「小写也能读到」——Get 按 canonical 查找。

## 2026-09-02 熔断失败率窗口只在失败路径判定，半开探测失败不会立即重开

- **现象**：按「10 样本 6 失败 → 应熔断」直译的测试永远不触发；按「探测失败一次应立即重新冷却」直译的测试同样失败。
- **根因**：窗口失败率只在 `OnFailure` 内判定（`OnSuccess` 只记样本不判定）——先失败后成功的序列在最后一次失败时样本数不足，成功再多也不会回头判定；且 trip 时连续失败计数清零，半开探测的单次失败只是重新起算的第 1 次，需再累计达阈值才重新冷却。
- **修复**：测试改为「先积攒到阈值样本 → 再来一次失败触发判定」与「探测失败需连续累计达阈值」；并把该语义写进 docs/10 交接注意。
- **教训**：带状态的判定逻辑（滑动窗口/计数器）要明确「判定时机挂在哪个动作上」，测试直译规格前先对齐实现的触发时机，否则用例永远空转。

## 2026-09-02 计费口径「数学等价」表述在测试断言上天差地别

- **现象**：写计费单测时三处断言与实现输出差了 1e6 倍或精度错位（如期望 72800 实际 73、期望 700 实际 1、期望 1500000 实际 1000001）；注释口径与实现传参互相矛盾（注释说「变量为百万 tokens」，实现传原始 tokens 且公式带 /1e6 因子）。
- **根因**：tiered_expr 变量单位存在两种数学等价表述——「原始 tokens × $/M 单价（值=micro-USD，quota=值×500000/1e6）」与「百万 tokens × $ 单价（值=美元，quota=值×500000）」——实现选了前者，注释按后者写，测试断言照注释写，三方不自洽；另有 GroupRatio 回退语义（未配置组回退 default 组值而非 1.0）与注释预期不一致。
- **修复**：以任务规格公式（×500000/1e6 因子）与黄金样例实测数值双重裁决口径为「原始 tokens 数、micro-USD」，修正三处断言与四处注释，并把口径锚点写进 docs/04/10 与 ADR 0004。
- **教训**：单位口径必须在注释、公式因子、测试断言三处同时自洽才可动手写测试；实测样例数值是裁决口径争议的最强事实源；类似「X 与 X/1e6」的等价表述务必选定一种并全库统一。

## 2026-09-02 异步日志 channel 缓冲小于瞬时投递量导致静默丢日志

- **现象**：logwriter 批量测试投递 100 条只落库 65 条，无任何报错；并发场景同样出现日志缺失。
- **根因**：Submit 为非阻塞设计（channel 满即丢弃并计数，保证不阻塞转发主链路），测试默认 Buffer 64 小于连续投递峰值 100，超出部分全部走丢弃路径——设计行为在低容量配置下表现为「丢数据」。
- **修复**：测试 Buffer 提到 128（大于峰值）并显式断言丢弃计数为 0；丢弃计数器本身纳入断言，让「丢了多少」可观测。
- **教训**：非阻塞队列的容量必须按「最大瞬时投递量」估算，宁可富余；凡「满了就丢」的设计，测试必须断言丢弃计数，不能假装不丢；生产容量配置要写进文档。

## 2026-09-02 unlimited 令牌只豁免冻结未豁免结算，账本被反向补扣

- **现象**：unlimited 令牌走完一次请求后 `remain_quota` 从 0 变成 −10——被扣了 10（冻结为 0、实结 10 的差额被当成补扣）。
- **根因**：unlimited 语义在 Freeze 处跳过（frozen=0），但 Settle(frozen=0, actual=10) 仍执行，差额 −10 被理解为「实际比预扣多扣 10」而调 adjust 反向补扣——豁免只挂在流水线的一环，没有覆盖整条链。
- **修复**：Settle 调用点加 `if !tok.UnlimitedQuota` 判断（RefundFull 本就有判断），unlimited 令牌冻结/结算/退款三级全跳过，日志仍记实结 quota 并标记 detail.Unlimited。
- **教训**：「豁免/跳过」类语义必须覆盖整条事务流水线（冻结→结算→退款），漏掉任何一环都会造成账本不对称；测试要对豁免路径断言「账本零变动」而非只断言响应正确。

## 2026-09-02 robocopy 复制单个文件返回 exit=16

- **现象**：用 robocopy 把暂存目录的单个文件复制回仓库报 exit=16（严重错误，什么都没复制）；复制整个目录时同一命令却正常（exit 1-7 均为成功）。
- **根因**：robocopy 语法要求源为目录，单文件场景写法无效直接报致命错误；而 Write 工具受限于工作区，工作区外仓库的文件更新必须经暂存目录中转。
- **修复**：单文件复制一律用 `Copy-Item -Force`；整目录同步才用 `robocopy src dst /E`（exit 0-7 视为成功）。
- **教训**：robocopy 是「目录复制器」，不要拿它复制单文件；脚本化复制流程要按「单文件 Copy-Item / 整目录 robocopy」分流，并对 robocopy 退出码做 0-7 白名单判断。

## 2026-09-02 本地竞品词扫描漏扫未跟踪文件，提交前假阴性

- **现象**：本地扫描报「竞品词扫描通过」后 push，CI 竞品词扫描 job 失败，命中 `internal/billing/golden_test.go`——竞品词自检测试为断言「黄金文件不含禁用词」，把竞品词列表硬编码进了测试源码，自己成了扫描命中源。
- **根因**：两因叠加——①本地扫描的文件清单来自 `git ls-files`，未跟踪的新目录（当时 internal/billing/ 尚未 git add）完全不参与扫描，本地拿到的「通过」是假阴性；②CI 扫的是已提交全集，本地与 CI 的扫描范围天然不一致。
- **修复**：①本地扫描清单并入 `git ls-files --others --exclude-standard`（未跟踪文件纳入扫描）；②自检测试改为从 `.github/competitor-words.txt` 读词表（单一事实源），测试代码内零竞品词。
- **教训**：基于 git 文件清单的本地检查对未跟踪文件存在天然盲区，提交前检查必须在 `git add` 之后跑，或清单显式并入 `--others`；「自检类」测试不要为断言把被检对象写进源码，应从外部事实源读取。

## 2026-09-03 会话篡改测试偶发失败：固定替换字符可能与原字符相同

- **现象**：TestSessionTamperRejected 在全包测试中偶发失败（篡改 sign 后应无效），单独重跑却通过；出现频率极低且随时间漂移。
- **根因**：篡改方式是把 cookie 中部/末位替换为固定字符 'A'/'B'——当原位置字符恰好也是 'A'/'B'（base64 字符集 64 个，约 1/64 概率）时「篡改」实际未变，签名仍有效，断言必失败；cookie 内容含时间戳，字符随时间漂移，于是表现为低概率偶发。
- **修复**：替换目标改为确定不同的字符（原字符为 'A' 则用 'B'，否则用 'A'），保证 payload/sign 必然改变。
- **教训**：「变异类」测试断言变异后行为改变的前提是变异确实发生——固定变异值与原值可能撞车，必须用「与原值确定不同」的变异；偶发失败的测试先怀疑时序与共享状态，其次检查是否存在概率性「无效变异」。

## 2026-09-03 独立构造 TokenAuth 实例测不出写后失效挂接缺失

- **现象**：令牌管理端点写后失效鉴权缓存的集成测试，用 `gateway.NewTokenAuth(st)` 新建实例验证：禁用令牌后 Authenticate 仍通过，误以为挂接缺失；而实际上挂接代码是好的。
- **根因**：管理面 Handler 持有的是 main 装配的 Gateway 内部 TokenAuth 实例，`Invalidate` 只清**该实例**的缓存；测试另建的实例缓存独立，禁用后它自己的缓存里仍是旧 enabled 快照（缓存命中路径仍会 validateToken 校验快照，不会回库）。
- **修复**：测试改用 `h.gw.Auth()` 拿与管理面同一个实例，失效挂接行为得以真实验证。
- **教训**：验证「写后失效/通知/广播」类挂接时，观察者必须是被挂接的同一个实例——新建实例测的是隔离世界；凡带进程内缓存的组件，测试要用生产装配路径拿实例，而非自己 new。

## 2026-09-03 PowerShell 中文引号拆断 git commit 命令

- **现象**：`git commit -m "...含“中文引号”..."` 报 `error: pathspec '裸对象丢' did not match`，提交信息被截断。
- **根因**：PowerShell 把中文全角引号“”当作定界符参与解析，-m 参数在中文引号处被拆断，后半段变成 git 的多余 pathspec。
- **修复**：提交信息写入临时文件（LF 归一化），用 `git commit -F <file>` 传入；含任何中文标点的提交信息一律走此路径。
- **教训**：Windows PowerShell 5.1 对非 ASCII 标点的命令行解析不可靠，长/含标点的参数都应走文件中转（-F/-MessageFile），不要内联。

## 2026-09-03 JSX 属性字符串不支持反斜杠转义

- **现象**：Channels.tsx 一处 `extra="...\"set\"..."` 形式的 JSX 属性在 tsc 下报 TS1127
  Invalid character，报错行落在字符串中部而非引号处。
- **根因**：JSX 属性字符串字面量不是 JS 字符串，不支持反斜杠转义——`\"` 不表示引号字符，
  而是提前终止属性字符串，后续内容被当裸 token 解析。
- **修复**：含引号/特殊字符的文案改用 JS 表达式形式：`extra={'...含 " 引号的字符串...'}`。
- **教训**：JSX 属性里只有 `{'…'}` 才是真 JS 字符串；文案只要含引号或反斜杠就用表达式形式，
  不要依赖属性字符串内的转义。

## 2026-09-03 事务内的状态迁移标记不能随错误回滚

- **现象**：兑换码过期语义初版推演发现：事务内发现过期 → 标记 status=4 → return err
  → 事务外映射 4xx——标记会随事务回滚丢失，过期码下次兑换会重复校验重复标记，状态永不收敛。
- **根因**：把「标记（需持久化的副作用）」和「拒绝（响应映射）」混在同一个错误返回路径里，
  err 语义在事务框架内必然触发回滚。
- **修复**：标记后 return nil 让事务提交，用外层布尔量（expired）区分「核销成功」与「已标记
  过期」，事务外再映射 400 拒绝。
- **教训**：事务内 return err = 全部副作用回滚；需要持久化的状态迁移标记必须随事务提交，
  拒绝语义放事务外——「标记」与「拒绝」是两个动作。

## 2026-09-03 滚动窗口步进次数要按循环边界推演，不能直觉外推

- **现象**：budget 相位对齐测试按直觉断言「过期 50h 的 24h 窗口重置后边界 = 旧边界 + 48h」
  实际 +72h。
- **根因**：步进循环语义是「cursor ≤ now 就继续推进」，old=now-50h 时 +24h/+48h 两个边界
  均仍 ≤ now，循环会再推进一次到 +72h——直觉把「跨了 3 个窗口」当成了「推进 2 次」。
- **修复**：测试改为 old=now-30h（+24h 仍 ≤now、+48h 覆盖 now），期望 old+48h；期望值按
  「cursor.After(now) 才停」的循环边界推演。
- **教训**：写「逐周期步进」类断言前，先把循环终止条件（≤ 继续推进 / > 停止）在纸上过一遍
  样例；「跨 N 个窗口」与「步进 N-1 次」直觉容易差一。

## 2026-09-03 gofmt -w 批量执行后必须复验 -l 为空（单次可能静默漏写）

- **现象**：`gofmt -w` 9 个文件后紧跟 `gofmt -l` 仍列出其中 2 个；复跑 `gofmt -w` 同样 2 个
  文件后 -l 为空。期间无任何报错、退出码 0。另同会话 http.Header 字面量小写 key 第二次
  踩中（新测试用 "x-api-key" 造 401）——本文已有同款条目，动手前未先翻记录。
- **根因**：疑似 Windows 文件锁/杀软瞬时占用导致个别写入静默失败；重复踩坑则纯属未执行
  「排查前先翻本文」纪律。
- **修复**：gofmt -w 后统一复验 `gofmt -l <scope>` 输出为空才算完成；Header 字面量一律
  canonical 形式（与 2026-09-02 条目一致）。
- **教训**：批量机械改写类命令（格式化/重命名）完成后必须复验，不能假设单次执行全部生效；
  排查前先翻本文——重复踩坑比新坑更浪费。

## 2026-09-03 控制台守卫探针误用管理端点，普通用户被误跳登录页

- **现象**：浏览器验收发现普通用户登录后被 navigate('/login') 弹回登录页，控制台无法
  进入；页面无报错，仅 403「需要管理员权限」toast 一闪而过。
- **根因**：ConsoleLayout 会话探针用管理端点 GET /api/option（root 专属）判断「已登录」
  ——普通用户会话合法但无 root 权限，403 落入探针 catch，与「未登录」混为一谈统一跳
  登录页。前端探针 catch 未区分 401（会话失效）与 403（权限不足）。
- **修复**：探针改用登录态自视端点 GET /api/user/self（最低权限端点，任何登录用户可读），
  响应顺带刷新本地会话元数据；菜单按角色渲染（ADMIN_ONLY_KEYS 集合过滤）+ 普通用户
  直访 root 专属路径回看板兜底；配套新增 GET /api/token/mine（所有权作用域）供普通
  用户视图替代管理列表。

## 2026-09-03 OAuth redirect_uri 的 scheme 信任 X-Forwarded-Proto（反代 TLS 终结）

- **场景**：M3-wave2 OAuth authorize/callback 需要 Absolute callback URL
  （`{scheme}://{host}/api/oauth/:provider/callback`），服务在反代后面拿不到真实 scheme
  （`r.TLS == nil`），直接用 http 会导致 provider 回调 http 而 site 配 https 被
  redirect_uri mismatch 拒绝。
- **实现**：scheme 解析顺序 = `X-Forwarded-Proto` 首段（逗号分隔取第一段并 TrimSpace）
  → `r.TLS != nil` 则 https → 缺省 http；Host 取 `r.Host`（含端口）。
- **权衡（信任边界）**：`X-Forwarded-Proto` 可被客户端伪造——本服务把它仅用于
  redirect_uri 的 scheme 推导，不用于安全决策（鉴权/cookie Secure 位不依赖它）；生产
  反代应覆写（而非透传）该头，恶意头在最外层反代被清洗。若未来 cookie 启用 Secure 位，
  必须改由反代注入的受信头或配置项决定，勿复用本推导。
- **教训**：反代场景的 scheme/host 类推导只服务于「拼 URL」这类非安全决策；安全属性
  必须来自受信配置面（反代覆写或显式配置），且注记部署文档。

## 2026-09-03 OIDC userinfo 取 sub 信任 TLS 通道不验 ID token 签名（权衡注记）

- **场景**：M3-wave2 oidc provider 登录需要外部身份标识。标准 OIDC 有两条路：解析
  ID token（验签名/JWT 库）或 userinfo 端点（Bearer access_token）。
- **实现与权衡**：选 userinfo 取 `sub`——token 从 provider token 端点经 HTTPS 直接
  取回（无中间人转发面），access_token↔userinfo 属同一 TLS 通道内的服务端直连；验

  token 携带的其它 claims）。风险面：若 token 端点响应被同进程内劫持（不存在跨信任
  边界传递），影响限于错误登录身份，且身份绑定有复合唯一约束兜底。若未来需要
  id_token 中的额外 claims 或离线验证，再引入 golang.org/x/oauth2 + 核心库。
- **教训**：身份认证链路的「省一步」必须有明确的信任通道论证（token 从授权服务器
  TLS 直达、不经过客户端中转），并把权衡写进 docs/05 契约与本文，后续维护者不致
  误判为遗漏。
