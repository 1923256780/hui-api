# 02-环境搭建与命令

> 与 AGENTS.md 第 3 章保持一致；本文补充安装细节。命令以 Windows PowerShell 5.1 为主，Linux 侧命令用于部署。

## 一、依赖安装

### Go（≥ 1.23）

Windows 两种方式（本机实际采用方式 B）：

- 方式 A：`winget install --id GoLang.Go -e`（需可直连 go.dev 下载 MSI）；
- 方式 B（免管理员）：从镜像下载 `go1.2x.x.windows-amd64.zip`（golang.google.cn/dl 或 mirrors.aliyun.com/golang），解压到 `D:\EngineeringFiles\tools\`，得到 `tools\go\bin\go.exe`，再把该 bin 目录追加到用户 PATH（建议用 `[Environment]::SetEnvironmentVariable(...,'User')`，等效 setx 且无 1024 字符截断风险）。

验证：

```powershell
go version   # 新开 shell 生效；当前会话可用绝对路径调用
```

### Node（≥ 20）与 npm

本机已有 v24.13.0 / npm 11.6.2。Linux 部署机不需要 Node（前端产物本地构建后嵌入）。

### gh（可选）

GitHub CLI，用于建仓/发版。`winget install GitHub.cli`。

go env -w GOPROXY=https://goproxy.cn,direct

## 三、常用命令（hui-api）

| 用途 | 命令 |
| --- | --- |
| 构建 | `go build ./...` |
| 输出二进制 | `go build -o bin/hui-api.exe ./cmd/hui-api` |
| 全量测试 | `go test ./...` |
| 静态检查 | `go vet ./...` |
| 本地运行 | `go run ./cmd/hui-api -addr :3100` |
| 版本信息 | `go run ./cmd/hui-api -version` |
| 健康检查 | `curl http://127.0.0.1:3100/health` |
| 状态自检 | `curl http://127.0.0.1:3100/api/status` |
| 一键验证 | `powershell -ExecutionPolicy Bypass -File scripts/build.ps1 verify` |
| 一键构建 | `powershell -ExecutionPolicy Bypass -File scripts/build.ps1 build` |
| 仅构建前端 | `powershell -ExecutionPolicy Bypass -File scripts/build.ps1 web` |
| 竞品词扫描 | `powershell -ExecutionPolicy Bypass -File scripts/check-competitor-words.ps1` |

`scripts/build.ps1` 目标说明（M1-wave1 起）：

- `verify` = vet + test + build；`build` / `test` / `vet` / `run` 分别对应单项；
- 所有 Go 目标执行前都会先跑 `Ensure-WebDist`：`web/dist/index.html` 缺失时自动
  `npm ci`（有 lock 文件）+ `npm run build`；npm 不可用或构建失败时回退写入占位
  `index.html`，保证 `go:embed` 编译不因缺 dist 而失败（CI go job 有同样的占位步骤）；
- 占位页仅保编译通过，**正式发布前必须确认 dist 为真实前端产物**（看 `npm run build` 输出）；
- `web` 目标只构建前端；web/ 目录不存在时跳过（CI 同样按目录存在与否自动启用）。

前端手工构建（web/）：

```powershell
cd web
npm ci
npm run build   # 产物 dist/，经 go:embed 嵌入
```
