# 04-计费与配额设计

> 状态：设计稿（M2 落地时按本文实施）。计费是 hui-api 的可信底线：宁可拒绝请求，不可错扣一分。

## 一、quota 单位

- 整数计费单位，**500000 quota = $1**；
- 价格配置以「每百万 tokens 的美元单价」表达（`p`=输入价、`c`=输出价、`cr`=缓存读价等），落库与结算统一换算为 quota。

## 二、三种计费模式

### 1. classic_ratio（倍率模式）

```
quota = (prompt_tokens * model_ratio + completion_tokens * completion_ratio)
        * group_ratio * quota_per_unit / 1e6
```

- 适配大多数模型的简单线性计价；
- 倍率配置存于 options 运行轨，支持热更。

### 2. tiered_expr（表达式模式）

- 每个模型配置一段计费表达式，支持自定义 `tier()` 函数（阶梯定价：按用量/上下文长度分档）；
- 表达式入参：`p`（输入单价）、`c`（输出单价）、`cr`（缓存读单价）及 tokens 计数；
- 表达式引擎自研实现白名单运算（四则、比较、tier/round 等），禁止任意代码执行；
- 适用有阶梯价、缓存价的模型。

### 3. 按次模式

- 固定价格/次（quota/次），不依赖 tokens 计数；
- 适合固定定价的模型与工具类端点。

> 三模式按模型粒度配置，优先级：按次 > tiered_expr > classic_ratio；模式声明与配置变更均走 options 热更。

## 三、预扣费 + 多退少补

1. 请求进入时按 `max_tokens` 与输入长度估算预扣 quota，先冻结（扣减余额）；
2. 响应完成后按实际 usage 结算：实际值 < 预扣 → 退还差额；实际值 > 预扣 → 补扣差额；
3. 补扣允许透支到负数，但负数余额会触发拒绝后续请求；
4. 结算明细写入 logs，预扣额与实结额都可追溯（对账依据）。

## 四、流中断全额退款

- 流式请求在输出完成前，若上游连接中断/客户端断开导致无法取得完整 usage：
  - 已知部分 usage：按已知部分结算（保守取值）；
  - usage 完全不可得：**全额退款**（退还全部预扣），并记日志标记 `refund_full`；
- 设计取向：中断场景宁可少收不多收。

## 五、未配价硬拒绝

- 请求的模型在渠道清单中但没有任何价格配置 → **直接拒绝**（HTTP 4xx，明确错误信息），绝不按 0 价放行；
- 「先上线后补价」通过管理面配置完成，配置热更即时生效；
- 该行为有黄金测试集用例固化，防止回归。

## 六、黄金测试集

- 概念：一组「输入（模式配置 + tokens 计数）→ 期望 quota」的固定用例，随代码版本维护；
- 覆盖：三种模式、tier() 阶梯边界、四舍五入边界、预扣/结算/退款全链路、未配价拒绝；
- 任何计费相关改动必须全量跑通黄金测试集，CI 阻断失败；
- 用例数据文件与断言工具在 M2 里程碑落地（internal/billing/golden/）。
