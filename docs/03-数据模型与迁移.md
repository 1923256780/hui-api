# 03-数据模型与迁移

> 状态：已落地（M1-wave1，2026-09-02；M3-wave1 schema v4，2026-09-03）。列定义以 `internal/model` 与 `migrations/*.sql` 双源为准，本文描述设计意图与落地差异。

## 一、总览

SQLite 单库，八张核心表：

| 表 | 职责 |
| --- | --- |
| channels | 上游渠道配置：地址、密钥、模型清单、优先级/权重、状态 |
| tokens | 访问令牌：哈希、额度、预算周期、限流、标签 |
| users | 用户与余额（M3-wave1 增邀请/两步验证列） |
| redemptions | 兑换码：面值、状态、核销记录 |
| options | 运行时配置（key-value），运行轨热更的数据源 |
| logs | 请求与计费日志，对账的事实来源 |
| user_identities | 第三方身份绑定（M3-wave1）：user ↔ (provider, provider_uid)，复合唯一 |
| topup_orders | 在线充值订单（M3-wave1）：订单号、网关、金额与到账 quota、状态机 |

## 二、quota 单位约定

- quota 为整数计费单位，**500000 quota = $1**（代码常量 `model.QuotaPerDollar`）；
- 所有价格配置、余额、兑换码面值统一换算为 quota 存储，浮点只在展示层出现；
- 任何计费表达式最终产出 quota 整数（四舍五入），中间过程可用浮点，落库必须是整数。

## 三、列设计要点（行业通用语义）

列名与现有 LLM 网关生态的通用语义同名同义（如渠道表的 `base_url`/`models`/`priority`/`weight`/`status`，日志表的 `model_name`/`quota`/`prompt_tokens`/`completion_tokens`/`use_time` 等），目的：

1. 语义自解释，降低新贡献者上手成本；
2. 用户从其他部署形态迁移时，数据可用通用 SQL 工具直接映射导入，不需要猜测字段含义。

### tokens 表的增强列

相对基础能力，tokens 表显式设计以下列：

| 列 | 说明 |
| --- | --- |
| `key` | 令牌明文（仅兼容展示用，非空场景保留） |
| `key_hash` | SHA-256(明文)，唯一索引；鉴权一律走哈希查找 |
| `budget_duration` | 预算周期（如 24h/7d/30d/monthly），配合周期重置额度 |
| `tpm_rpm` | TPM/RPM 限流配置（JSON：`{"tpm":..,"rpm":..}`），M2-wave1 接入转发链路 |
| `tags` | 标签列表（JSON 数组），用于分组管理与报表聚合 |
| `group` | 令牌分组（M2-wave1）：计费 GroupRatio 组倍率与分组级限流的归属组，缺省 `default` |
| `model_limits` | 模型白名单（逗号分隔，空=不限），转发链路强制校验（M2-wave1） |
| `allow_ips` | IP 白名单（逗号分隔 IP/CIDR，空=不限），鉴权后校验（M2-wave1） |

> 安全默认值：`key_hash` 是鉴权唯一依据；`key` 列允许为空，创建时明文仅返回一次。

## 四、迁移规则

1. schema 变更必须编写版本化迁移脚本（up-only，向前兼容一版）；
2. 禁止修改历史迁移；发现历史迁移有误，新迁移修正；
3. 迁移在进程启动时自动执行，成功后写入 `options.schema_version`；
4. 迁移前自动触发备份（见 06-部署与运维.md，M5 常态化前为手动）；
5. 涉及表结构的改动必须同步本文并更新核心表概览。

## 六、落地说明（2026-09-02，M1-wave1）

实现与本文设计完全一致，以下为补充的落地细节：

- **双源 DDL**：`migrations/0001_init.sql` 为基线的文档源，`TestDDLEquivalence` 测试在 CI
  固化其与 AutoMigrate 产物逐表列集合一致；改模型必须同步该 SQL。
- **连接模型**：写池单连接、读池独立（ADR 0003）；PRAGMA 经 DSN 对每个连接生效，
  断言见 `TestPragmas`。
- **状态枚举**：`channels/tokens/users.status` 共用 1=启用、2=手动禁用（`model.StatusEnabled/StatusDisabled`），
  3=熔断中仅 channels 使用；`redemptions.status` 为 1=未使用、2=已核销、3=已作废、
  4=已过期（核销路径惰性标记，M2-wave3）。
- **时间语义**：所有时间列 unix 秒（int64）；`expired_time=-1`（`model.EpochForever`）表示永不过期。
- **options 元数据**：`schema_version` 键由迁移框架写入 options 表，随运行轨配置一起被
  `config.Runtime` 读入快照（可经 `Get("schema_version")` 读取）。
- **logs.detail**：新增计费依据 JSON 列（`{"mode":..,"expr":..,...}`），供 M2 对账反向重算；
  `use_time` 单位为秒。
- **布尔列**：`tokens.unlimited_quota`、`logs.is_stream` 落库为 numeric（SQLite 布尔 affinity）。
- **M2-wave1 新增列（schema v3，迁移 0003）**：`tokens.group`/`users.group` 缺省
  `'default'`（组名语义与 `GroupRatio`/`ModelRequestRateLimitGroup` 键一致）；
  `users.auth_version` 为会话版本号，改密时递增使旧签名 cookie 全部失效；
  `tokens.model_limits`/`tokens.allow_ips` 为白名单文本列，空值表示不限。
- **M3-wave1 新增（schema v4，迁移 0004_m3_commercial）**：
  `users` 加 5 列——`aff_code`（邀请码，缺省空串，索引）、`inviter_id`（邀请人用户 id，
  缺省 0，索引）、`aff_history_quota`（邀请奖励累计入账，缺省 0）、`totp_secret`
  （两步验证密钥，缺省空串，**JSON 序列化豁免 `json:"-"`，任何端点不得输出**）、
  `totp_enabled`（两步验证开关，缺省 false）；
  新表 `user_identities`——`user_id`（索引）、`provider`（≤32）/`provider_uid`（≤128）
  复合唯一，一个第三方身份最多绑定一个用户、同一用户可绑定多个 provider；
  新表 `topup_orders`——`order_no`（≤64，唯一索引）、`user_id`（索引）、`gateway`
  （≤16）、`amount_cents`/`currency`（缺省 'CNY'）、`quota`（到账额度）、`rate`
  （汇率快照）、`status`（1=待支付 2=已支付 3=失败 4=过期）、`trade_no`（≤128，索引）、
  `detail`（≤1024，网关回调原文）、`paid_time`/`created_time`（unix 秒）；
  `TestDDLEquivalence` 表清单同步扩为八表（AutoMigrate 与迁移 SQL 逐表列集合一致）。
