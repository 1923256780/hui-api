# ADR 0003 — 存储层落地：单写多读连接池 + AutoMigrate 基线迁移 + 原子快照热更

> 状态：已接受 | 日期：2026-09-02 | 决策人：hui-api 作者

## 背景

M1-wave1 需要把 docs/03 的六表设计落成代码。三个关键问题需要定案：

1. SQLite 是单写者数据库，进程内连接池怎么开才能兼顾并发读与写入安全；
2. schema 演进用什么机制管理：纯手写 SQL 迁移还是 ORM AutoMigrate；
3. 运行轨配置（options 表）如何在进程内安全热更，读侧不看到半新半旧状态。

约束：零 CGO（glebarez 纯 Go 驱动）、单机单进程、小内存（服务器 400M 档位）、
迁移必须幂等且禁止修改历史迁移（docs/03 第四节）。

## 决策

### 1. 双连接池：写池单连接，读池独立多连接

- `store.Open` 打开两个 `gorm.DB`：写池 `SetMaxOpenConns(1)`（写天然串行化，杜绝
  `database is locked` 竞争），读池默认 4 连接承载并发查询；
- PRAGMA 经 DSN 在**每个连接建立时**执行：`journal_mode=WAL`、`synchronous=NORMAL`、
  `busy_timeout=5000`（synchronous/busy_timeout 是连接级属性，不能只设一次）；
- WAL 模式为库级持久属性，读写连接可安全共存，读不阻塞写、写不阻塞读。

### 2. 迁移：AutoMigrate 作 0001 基线，后续版本走 up-only SQL

- 版本 1（基线）：`store.Migrate()` 用 AutoMigrate 以 `internal/model` 为**唯一源**建六表，
  成功后写 `options.schema_version=1`；重复执行幂等；
- 版本 ≥2 的 schema 变更：编写 up-only SQL 迁移脚本叠加执行，`SchemaVersion` 常量随行递增，
  历史迁移禁改（修错靠新迁移）；
- `migrations/0001_init.sql` 作为基线的**文档源**（手写等价 DDL），与代码源双源一致，
  由 `TestDDLEquivalence` 测试固化：两套建表结果按 `PRAGMA table_info` 列集合逐一比对。

### 3. 运行轨配置：options 全量快照 + atomic.Value 原子替换

- `config.Runtime` 维护不可变快照 `{Version, Values}`，`Reload()` 读全量 options 后
  递增版本号并经 `atomic.Value` 整体替换；读侧要么看到完整旧值、要么完整新值；
- 每次成功 Reload 版本号 +1，`/api/status` 暴露 `config_version` 供管理面展示；
- 管理面（M2）写 options 后调用 `Reload()` 即热生效，无需重启。

### 4. hook 旁路：有界队列，队列满丢弃并计数

- `hook.Dispatcher` 内置容量 256 的 ring（channel）+ N 个 worker goroutine；
- `Dispatch` 非阻塞：入队失败即丢弃并 `dropped` 原子计数，主链路零等待；
- 单 hook 的 panic/错误在单 hook 粒度隔离（per-hook recover），不影响其他 hook 与后续事件；
- 事件携带 `IdempotencyKey`，投递语义为「至少一次尽力而为」，消费方按幂等键去重副作用。

## 备选方案（含被拒绝理由）

1. **单连接池（读写共用）**
   - 被拒：SQLite 并发写下 `SQLITE_BUSY` 风险集中；写池单连接是最简单的串行化手段，无需应用层写锁。
2. **纯手写 SQL 迁移（含 0001）**
   - 被拒：GORM 模型已是列定义的唯一事实源，再手写一套建表 SQL 会出现双源漂移；基线用 AutoMigrate、
     测试比对文档源 DDL，漂移在 CI 即暴露。
3. **配置热更用轮询 + 互斥锁逐键读**
   - 被拒：逐键读存在键间不一致窗口；全量快照 + 原子替换实现同样简单且无撕裂。
4. **hook 同步调用（无队列）**
   - 被拒：违反 docs/01 设计点 6——旁路动作不得进入转发主链路时延。

## 后果

- 正面：写路径天然免锁；迁移幂等可重复启动；热更快照无撕裂、可观测（version 单调递增）；
  旁路不拖垮主链路。
- 负面：写池单连接使大批量写入吞吐受限（个人/小团队规模可接受，见 ADR 0001 同款权衡）；
  AutoMigrate 不会删列，后续字段废弃需在新迁移中显式处理。
- 执行要求：所有写操作必须经 `store.Write`，读优先走 `store.Read`；新增运行轨配置键一律
  「代码内默认值 + options 覆盖」，options 只存非默认值（docs/03）。
