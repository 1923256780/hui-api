# ADR 0009 — 生产旁路部署拓扑与资源限额

> 状态：已接受 | 日期：2026-09-04 | 决策人：hui-api 维护者

## 背景

M4-wave2 需把 hui-api 部署到生产服务器与旧网关（legacy）**并存旁路验证**：2GB 内存小机型（实测 available ≈1.3GB），旧网关以 systemd 服务占用 3000 端口服务真实流量。约束：

- 生产服务与其数据是唯一真本，旁路期任何干扰（重启/占端口/写库）都不可接受；
- 小内存机型上双进程并存，无护栏的内存增长可能触发整机 OOM 波及生产；
- 旁路库需要真实生产数据的形态（令牌 key_hash、渠道、计费配置）做切换可行性验证；
- 服务器安全组/防火墙属于生产变更（红线），旁路期不得改动。

## 决策

- **旁路只绑 `127.0.0.1:3100`（SSH 隧道访问，公网不可达）**：config `addr: "127.0.0.1:3100"`，
  不放行安全组、不动 Nginx；管理台/冒烟一律经 SSH 隧道或服务器本机 curl。部署布局
  `/home/ubuntu/hui-api/{bin,config,data,logs}`，数据库为独立文件（`data/hui-api.db`），
  与生产库物理隔离。
- **资源限额双层**：systemd `MemoryMax=400M`（硬护栏，超限 OOM kill + `Restart=on-failure`
  拉起，3s 退避）+ `Environment=GOMEMLIMIT=120MiB`（软上限，Go GC 逼近时积极回收）。
  实测空闲 RSS ≈8.5MB、冒烟后峰值 <30MB，400M 护栏留 10 倍余量；2GB 机型双进程并存
  实测 available ≈1.39GB。
- **迁移源用备份副本，先 migrate 后 start**：旁路库数据来自服务器每日 cron 备份的
  `.db.gz` 副本（在线备份 API 产物），全程不打开生产库文件；启动顺序为 migrate → start——
  对账 13 项指标的前提是目标库为未上线库（ADR-0008），先 start 会因 root 引导等写入破坏
  行数对账。systemd 单元先 enable（不 start），migrate 成功后再 start。
- **SESSION_SECRET 服务器端生成一次固化**：`openssl rand -hex 32` 在服务器上生成并直接
  写入 config（chmod 600），密钥不落任何仓库/报告；重生成会失效全部管理台会话，故 config
  已存在时脚本跳过重生成（幂等）。
- **冒烟脚本可复跑且端口可覆盖**：`scripts/deploy-smoke-server.sh` 七项清单
  （health/status/RSS/迁移令牌 `/v1/models` 200/真实转发计费复核/journalctl 关键字/free -m），
  `HUI_BASE` 环境变量覆盖目标端口——3000 接管日的切换冒烟复用同一脚本。

## 备选方案（含被拒绝者及理由）

1. **旁路绑 `0.0.0.0:3100` + 安全组放行**
   - 被拒理由：扩大暴露面且需要动安全组（生产变更红线）；管理台/冒烟不需要公网可达，
     SSH 隧道已覆盖全部访问需求。
2. **不设资源限额，靠宿主机 OOM killer 兜底**
   - 被拒理由：整机 OOM 时 kill 目标不可控，大概率误伤内存最大的生产网关；双层限额
     （GC 软上限 + cgroup 硬护栏）把故障域收敛在 hui-api 自身，Restart 自动恢复。
3. **先 start 后 migrate（旁路库由服务自建）**
   - 被拒理由：服务启动会建空库并引导 root 用户，随后 migrate 的对账必然出现行数
     MISMATCH（退出码 1），强对账语义被破坏；先 migrate 后 start 是 ADR-0008 对账
     前提的自然推论。
4. **迁移源直连生产库文件（跳过备份副本）**
   - 被拒理由：工具虽是只读双层防御（mode=ro + query_only），但"旁路验证绝不触碰
     生产数据文件"是更简单的纪律——备份副本本身就是一致性快照，审计面也更清晰。

## 后果

- 正面：生产零影响（服务/数据/端口/安全组四不碰，实测全程旧网关 active 且无重启）；
  切换可行性获得锚点证据（迁移令牌 `/v1/models` 200 + 真实转发计费 quota=11 与演练一致）；
  内存双护栏使小机型并存风险可控；runbook 全程可复用旁路冒烟脚本。
- 负面：旁路库数据落后生产备份至多 24h（cron 周期），旁路验证结论对增量数据不敏感
  （schema/鉴权/计费口径不变）；切换日必须重置目标库重迁（对账语义前提，见 docs/06 第七节）。
- 中性/执行要求：旁路期 hui-api 库只允许冒烟类写入（无真实业务流量）；切换 runbook
  （docs/06 第七节）执行前重跑预检清单；config/报告文件权限维持 600；服务器上不遗留
  明文令牌临时文件（冒烟后即删）。
