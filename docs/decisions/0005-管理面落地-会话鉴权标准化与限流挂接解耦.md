# ADR 0005 — 管理面落地：会话鉴权标准化与限流挂接解耦

> 状态：已接受 | 日期：2026-09-03 | 决策人：hui-api 维护者

## 背景

M2-wave1 需要交付管理面 API（登录会话 + 六组 CRUD）与限流挂接（全局/分组/令牌 TPM/RPM），四类选型必须先裁决：

1. 密码哈希：登录校验与口令存储算法；
2. 会话载体：签名 cookie 的实现方式与失效机制；
3. 限流算法：滑动窗口/令牌桶的取舍与分组覆盖语义；
4. 管理面写语义：PUT 字段合并策略（行业竞品曾因裸对象合并丢字段）。

约束：单二进制自托管、零外部服务依赖、竞品 clean-room 边界（只借鉴语义不抄实现）、小步提交时间盒。

## 决策

- **密码哈希采用 `golang.org/x/crypto/bcrypt`**。任务书「自实现 bcrypt 校验+生成」的落点解释为：自建登录校验流程与哈希存储结构（users.password_hash、登录端点、改密重置），密码学原语本身使用标准库实现——手写密码学算法属于工程禁手（无好评审、无侧信道保障、x/crypto 已是事实标准且在 go.mod 生态内零运维成本）。
- **会话载体自实现 HMAC-SHA256 签名 cookie**：payload（uid/authv/exp）base64url + "." + HMAC 签名，hmac.Equal 恒时比较；**不引入 JWT**——本场景单服务单密钥、无跨域/多消费者需求，JWT 的 header/claims 灵活性与库依赖无收益。失效机制：`users.auth_version` 纳入 payload、在中间件层与库比对（不在签名层），改密递增即全端失效；会话 TTL 7d、HttpOnly+SameSite=Lax、无刷新续期（到期重登，管理台场景够用）。
- **限流采用手写滑动窗口**（`internal/ratelimit`）：`AllowRequest/RecordSuccess`（请求/成功分离，支持行业 ModelRequestRateLimit 的 Count/SuccessCount 语义）与 `AllowTokens/RecordTokenUsage`（令牌 TPM/RPM）双入口；`sync.Map` 分桶 + idle TTL/LRU 上限淘汰；**不引入 `golang.org/x/time/rate`**——令牌桶是平滑速率语义，与「固定周期内 N 次」的行业配置语义不匹配，且分组覆盖全局、共用周期、被拒不消耗配额等规则需要定制，滑动窗口百行内可测试可审计。被拒请求不记录（不消耗配额）、本机 429 不计入上游熔断失败计数（限流与熔断解耦）。
- **管理面写语义为整对象幂等替换**：PUT 请求对象显式声明全部业务字段（含零值生效），不用反射合并/部分更新——类型安全、语义可预测、同 body 重复 PUT 响应体一致；缺省归一化集中处理（status 0→启用等）；密钥类字段永不回显覆盖（channel.key 空=保留旧值）。

## 备选方案（含被拒绝者及理由）

1. **自实现 bcrypt 算法**
   - 被拒理由：手写密码学不可审计、侧信道风险高、与「自实现」的任务意图（校验流程自建）不符。
2. **JWT（golang-jwt）或 gorilla/sessions**
   - 被拒理由：单服务场景下 JWT 无跨服务收益反增依赖与密钥管理面；gorilla/sessions 的 store 抽象为多后端设计，本场景单 cookie 即可。
3. **golang.org/x/time/rate 令牌桶**
   - 被拒理由：平滑速率 ≠ 固定周期计数；分组覆盖、SuccessCount、被拒不消耗、Retry-After 精确秒数均需外挂定制，包装成本超过自写滑动窗口。
4. **PUT 反射合并 / JSON merge-patch（部分更新）**
   - 被拒理由：行业竞品裸对象合并已发生过丢字段事故（priority/weight 被清零）；显式整对象写可测试、可幂等断言，字段归一化集中一处。
5. **会话存库（DB session table）**
   - 被拒理由：每次请求查库 vs 本地验签，管理台读多写少场景验签零 IO；auth_version 比对虽需查库，但可复用中间件既有用户查询，无额外成本。

## 后果

- 正面：零新增运行时依赖（x/crypto 为扩展标准库）；会话与限流行为完全可测（本波 19+4+1 测试）；行业兼容键名（ModelRequestRateLimit*）降低迁移理解成本。
- 负面：auth_version 比对使每个管理面请求查一次用户（后续可加短 TTL 缓存）；滑动窗口为进程内存态，多副本部署需外置存储（当前单实例目标场景不受影响）。
- 中性/执行要求：SESSION_SECRET 生产必须固定（缺省随机生成重启即全端失效）；令牌写后必须 `Auth().Invalidate`（缓存对 invalid 结果也缓存）；限流参数变更走 /api/option 白名单热生效；凡涉计费改动回归黄金测试集。
