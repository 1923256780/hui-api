# 06-部署与运维

> 状态：M0 基线。M4 切换演练后按实际经验修订。

## 一、目标部署形态

- 单台 Linux 服务器（Ubuntu），systemd 托管单进程；
- SQLite 数据文件 + 定期备份；
- 生产监听 3000，旁路验证用 3100。

## 二、交叉编译

Windows 开发机（PowerShell）：

```powershell
$env:CGO_ENABLED='0'; $env:GOOS='linux'; $env:GOARCH='amd64'
go build -ldflags "-s -w -X main.version=v0.1.0 -X main.commit=<sha>" -o bin/hui-api-linux-amd64 ./cmd/hui-api
```

> 纯 Go SQLite 驱动 + `CGO_ENABLED=0`，任何平台可直接交叉编译出 Linux 二进制。

Linux 侧上传后：

```bash
chmod +x hui-api-linux-amd64 && ./hui-api-linux-amd64 -version
```

## 三、systemd 单元模板

`/etc/systemd/system/hui-api.service`：

```ini
[Unit]
Description=hui-api LLM gateway
After=network.target

[Service]
Type=simple
User=hui
WorkingDirectory=/opt/hui-api
ExecStart=/opt/hui-api/hui-api -addr :3000
Environment=GOMEMLIMIT=120MiB
Restart=always
RestartSec=3
# 内存护栏：SQLite 全内存缓存场景下的安全上限
MemoryMax=400M
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
```

要点：

- `GOMEMLIMIT=120MiB` 软上限，Go GC 在逼近时积极回收；
- `MemoryMax=400M` 硬护栏，超出由 systemd OOM kill，Restart 自动拉起；
- 结构化日志走 stdout/journald，`journalctl -u hui-api -f`。

## 四、备份策略

1. **迁移前自动备份**：进程启动执行 schema 迁移前，先对 db 文件做快照备份（`.db.gz`）；
2. **日常定时备份**：cron 每日 `sqlite3 .backup`（或停写窗口文件拷贝）→ gzip → 保留最近 14 份 + 每月 1 份；
3. **备份验证**：每月随机抽 1 份备份在临时目录解压、用 `sqlite3 integrity_check` 验证可开；
4. 备份文件不进 git（.gitignore 已排除 `*.db`/`*.db.gz`）。

## 五、M4 端口接管切换预案

现有旧网关运行于生产 3000 端口。hui-api 切换采用「旁路验证 → 接管 → 可回滚」三段式：

### 阶段 1：3100 旁路验证（不动生产）

```bash
./hui-api -addr :3100        # 新服务起在 3100
curl http://127.0.0.1:3100/health
# 用测试令牌完整验证：鉴权/路由/计费/日志
```

### 阶段 2：3000 接管

```bash
systemctl stop old-gateway && systemctl start hui-api   # 接管 3000
curl http://127.0.0.1:3000/health
```

### 阶段 3：回滚（两条命令）

```bash
systemctl stop hui-api && systemctl start old-gateway
```

> 回滚前提：旧服务未卸载、其数据文件未被破坏（hui-api 验证期使用独立 db 文件，不碰旧库）。接管后旧库保留至少一个观察期，再规划数据迁移。
