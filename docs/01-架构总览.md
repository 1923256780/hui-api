# 01-架构总览

> 状态：**活文档**。模块边界、目录结构、数据模型变化时必须同步本文，并在 `decisions/` 新增 ADR。

## 一、设计原则

1. 单二进制 + SQLite：部署面收敛到「一个进程 + 一个文件」；
2. 主链路最短：转发路径上只做必须的事，重活走异步旁路；
3. 可对账优先：任何一次扣费都能从日志表还原计算依据；
4. 失败可见：渠道/令牌/计费异常必须有结构化日志与状态沉淀。

## 二、目标架构：10 个设计点

### 1. Deployment 作为一等实体

版本号、监听地址、数据目录、备份策略、健康探针作为显式的部署配置项集中管理，而非散落在代码各处。二进制自带 `-version` 输出构建信息，供切换预案与运维核对。

### 2. 双协议 relay

统一转发内核对外暴露两种协议面：

- OpenAI 兼容：`/v1/chat/completions`（含流式）；
- Anthropic Messages：`/v1/messages`（含流式）与 `/v1/messages/count_tokens`。

两种协议在内部归一为统一请求描述（模型、消息、采样参数、流标记），响应侧再按入口协议还原。协议适配层与转发层解耦，适配层不做业务决策。
> 落地（M1-wave2，2026-09-02）：`internal/relay` 定义 Protocol 接口与公共工具（SSE 逐事件 flush、URL 拼接、usage 归一），`internal/relay/openai` 与 `internal/relay/anthropic` 为两个适配实现；归一结构 ParsedRequest 当前只携带路由所需字段（model/stream/端点标记），采样参数留在原始 JSON 由 param_override 直接改写，避免二次序列化失真。

### 3. 渠道路由与熔断

多渠道按优先级 + 权重调度；同一渠道连续失败达到阈值即熔断，进入半开探测后恢复。渠道状态（启用/禁用/熔断中）持久化，重启不丢失熔断现场。
> 落地（M1-wave2，2026-09-02）：`internal/gateway` 实现 Deployment 选择（priority 降序 + weight 加权随机）、熔断状态机（allowed_fails=3 / cooldown=5s / 429 立即冷却 / 分钟失败率>50% 且样本≥10）与 typed retry 策略表。熔断状态当前为进程内存态（重启清零，重启不保留熔断现场）；持久化挂接在 M3 管理面（channels.status=3 熔断中列已预留）。

### 4. billing 计费内核

三模式计费（classic_ratio / tiered_expr / per_call）、预扣费 + 多退少补、流中断全额退款、未配价硬拒绝。计费是独立内核模块，relay 只调用、不感知细节。详见 `04-计费与配额设计.md`。
> 落地（M1-wave3，2026-09-02）：`internal/billing` 三模式引擎（tiered_expr 引入 github.com/expr-lang/expr，tier() 单层语义，编译缓存并发安全）、价格解析（options 显式声明 > ModelRatio 隐式 classic > 内置 prices.json > ErrUnpriced）、预扣费账本（Estimate 上浮 20% 冻结 / 事务内条件 UPDATE 防透支 / Settle 多退少补 / RefundFull 全额退款）、内置价单 prices.json（go:embed + 启动校验含试求值）、异步请求日志（批量 flusher + 停机 drain）。结算挂接在 gateway.Serve：转发前冻结（403 拒绝）、Respond 成功后按 relay.Usage 多退少补（cache_read 从 PromptTokens 拆分防重复计费）、失败/流中断退款并标记 aborted、usage 缺失粗估标记 estimated。口径与选型取舍见 ADR 0004，公式实测见 docs/04 第七节。

### 5. store 统一存储层

GORM + glebarez 纯 Go SQLite 驱动。六表模型（channels/tokens/users/redemptions/options/logs）集中定义，版本化迁移框架管理 schema 演进。所有写操作经存储层，禁止散落裸 SQL。
> 落地（M1-wave1，2026-09-02）：`internal/model` + `internal/store`；连接模型与迁移机制见 ADR 0003。

### 6. hook 异步旁路

审计、通知、回调类动作走异步旁路队列，失败重试但不阻塞转发主链路，也不影响响应时延。旁路消息带幂等键，重复投递不产生重复副作用。
> 落地（M1-wave1）：`internal/hook`；有界队列满丢弃并计数，per-hook panic 隔离（ADR 0003）。

### 7. 配置双轨热更

配置分两轨：

- 启动轨：环境变量/启动参数，仅进程启动时读取（端口、数据目录等部署面）；
- 运行轨：options 表，管理面修改后热加载生效（渠道参数、计费配置、开关类）。

运行轨变更通过版本号/更新时间感知，热更不需要重启进程。
> 落地（M1-wave1）：`internal/config`；启动轨 = env > YAML > 默认值，运行轨 = options 原子快照热更骨架，管理面写 API 于 M2-wave1 交付（键白名单 + 写后 Reload()）。
> 计费配置热更（M1-wave3）：`billing_setting.billing_mode/expr/price`、`ModelRatio`、`CompletionRatio`、`GroupRatio` 均走运行轨，billing 引擎按 Runtime 版本号失效重建解析缓存（表达式编译缓存按文本跨热更复用）。

### 8. 令牌体系

令牌明文只在创建时返回一次，库内只存 SHA-256 的 `key_hash`；支持预算周期、有效期、TPM/RPM 限流、标签分组。鉴权走哈希查找，不暴露明文比对接口。

### 9. 兑换码与用户体系

兑换码批量生成、一次核销、额度入账可追溯；用户余额独立于令牌预算，支持按用户维度审计。

### 10. 可观测与对账

每次请求落 logs 表：协议、模型、渠道、令牌、耗时、quota 上下文。计费结果可由 logs 反向重算验证（对账）。结构化日志输出到 stdout，交给 systemd 收集。
> 落地（M1-wave3，2026-09-02）：logs 表写入走异步批量 writer（有界 channel 非阻塞 Submit + 攒批 flusher + 停机 drain）；logs.detail 记 billing_mode、token 明细（frozen/actual/prompt/completion/cache_read）、cache 命中、estimated/unlimited/refund_full 标记——quota 可由 detail 反向重算。

## 三、目录结构（目标态）

```
cmd/hui-api/          入口与依赖装配
internal/relay/       双协议适配与转发管道（openai/ anthropic/ 子包）
internal/gateway/     转发编排：鉴权、渠道选择、熔断、typed retry（目标名 internal/channel）
internal/override/    param_override 参数改写管道
internal/billing/     计费内核
internal/api/         管理面 HTTP API：登录会话、六组 CRUD、options 热更
internal/ratelimit/   滑动窗口限流（全局/分组/令牌 TPM/RPM）
internal/store/       GORM 模型、迁移、仓储
internal/config/      双轨配置与热更
internal/hook/        异步旁路
web/                  React 管理台（go:embed 嵌入）
```

> 落地进度（2026-09-03，M2-wave1）：`cmd/hui-api`、`internal/model`（store 的模型子包）、
> `internal/store`、`internal/config`、`internal/hook`、`internal/relay`（含 openai/anthropic 子包）、
> `internal/gateway`、`internal/override`、`internal/billing`（计费内核：引擎/账本/日志器/内置价单/黄金测试集）、
> `internal/api`（管理面：会话鉴权/六组端点/options 热更）、`internal/ratelimit`（限流挂接转发链路）、
> `web`（外壳 + go:embed 预留）已落地。目标目录名 `internal/channel` 落地为 `internal/gateway`：
> 渠道池/调度/熔断与转发编排职责同包协作紧密，拆分收益低于接口成本，M2 计费接入后视边界再评估。

## 四、请求生命周期（目标态）

```
客户端 → 鉴权(key_hash) → 令牌限流(tpm/rpm) → 模型解析
      → 计费预扣(estimate) → 渠道调度(优先级/权重/熔断)
      → relay 转发 → 响应还原(按入口协议) → 计费结算(多退少补)
      → 日志落库(logs) → 异步旁路(hook)
```
